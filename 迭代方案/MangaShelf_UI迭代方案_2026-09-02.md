## 一、现状诊断（经代码核实）

### 1. 文案过载 —— 界面像「带教程的网站」

| 位置 | 代码 | 问题 |
|---|---|---|
| 书库首页常驻说明段 | `LibraryView.tsx` 245–249 行 | 基线导入前，网格上方永远挂着一段 44 字的机制解释 |
| 扫描按钮 tooltip | `LibraryView.tsx` 221–226 行 | 两个变体各 30+ 字，解释内部索引机制 |
| 空状态提示 | `LibraryView.tsx` `emptyHint()` 534–561 行 | 每个分支都是完整教学句 |
| 设置页机制长文 | `SettingsView.tsx` 221–223 行 | 一段 90 字，解释首次导入、自动扫描、封面标更新、不删文件 |
| 阅读器常驻快捷键提示 | `ReaderView.tsx` 831–838 行 | footer 永久显示快捷键说明（三个变体） |
| 侧栏常驻状态行 | `App.tsx` 173–175 行 + `useLibrarySession.ts` | `statusMessage` 永久占侧栏底部；`runScan()` 同一句话同时 toast 和写侧栏 |
| 更新入口暴露实现细节 | `SettingsView.tsx` 411–414、450–455 行 | 直接显示 `qingyou0420/MangaShelf`、releases 路径和「已扫描目录」列表 |

核实的机制解释文案约 **6 处、合计 300+ 字符**常驻或半常驻。高端本地应用应是「行为自明 + 出问题才说话」，而不是预先解释自己。

空状态教学句示例：

> 选择本地书架文件夹，然后点右上角「导入现有书库」。首次导入只建立索引，不会把已有漫画标成更新。

### 2. 视觉层级弱 —— 一切都是等权重的灰色描边卡片

`App.css` 核实到的根因：

- **无真正的强调色**。`--accent: #1a1f2c` 就是墨色本身，主按钮、进度条、选中态全是近黑灰。收藏星 `#b45309` 是唯一彩色，且只在 hover 才出现。
- **万物皆 1px 边框卡片**：`.panel`、`.empty-hint`、`.continue-card`、`.library-tile`、`.sidebar-stats > div`、`.series-chapter-item` 全部同一套 `border: 1px solid var(--line) + border-radius`，没有海拔差异，封面不是主角。
- **侧栏与内容区几乎同色**：侧栏 `#fafafb` vs 页面 `#f4f5f7`，结构分区靠一根线撑着。
- **书库首页纵向堆叠混乱**：标题行 → 说明段落 → 失败列表 → 继续阅读卡 → 工具栏 → 网格。网格（真正的内容）被推到第四屏层级。
- **系列页动作行**（`SeriesView.tsx` 109–174 行）：一行最多塞 7 个控件——继续阅读、收藏、编辑、打开文件夹、重新扫描、选择封面、清除进度，主次不分。
- **阅读器「更多」菜单**（`ReaderView.tsx` 599–619 行）：翻页/滚动/双页/左开/右开是互斥模式，却渲染成 7 个无选中态的裸按钮（只有「封面单独」有 active 样式）。
- **原生控件**：筛选/排序/适配/主题全部是原生 `<select>`；删除、清进度、拖放设书架用 `window.confirm`（`useLibrarySession.ts` 186、507、542 行）——Windows WebView2 原生弹窗观感拉低质感。
- **暗色主题是补丁式的**：约 12 组 `.app-shell.theme-dark .xxx` 硬编码 hex 覆盖（46–104 行），不是 token 派生。
- **640px / 900px 响应式断点**（1328–1403 行）让桌面 app 带着「手机网站」基因。

### 3. 必须保护的行为（v2.5.1 基线，不可破坏）

- `baselineCompleted` 驱动按钮文字在「导入现有书库」↔「扫描书架」间切换（`LibraryView.tsx` 228–234 行）。
- 首次使用空状态必须保留「选择书架文件夹」按钮 + 导入引导（484–492 行）。
- `runScan` 中 `establishedBaseline` 分支的汇报语义（`useLibrarySession.ts` 298–306 行）。
- 测试已钉死：`LibraryView.test.tsx` 60–61、123 行断言按钮名；`App.test.tsx` 252、261 行断言「导入现有书库/扫描书架」和「已导入现有书库 1 部，已作为基准」。**这些不许动。**

## 二、设计原则（桌面本地漫画库，不是网站）

1. **封面即界面。** 漫画 app 最贵的视觉资产是封面。去掉 tile 描边，让封面自带投影和悬停反馈；系列页用封面模糊做氛围背景。
2. **行为自明，文案沉默。** 机制解释一律降级为 tooltip、一次性提示或删除；界面只在「出错」和「空」时说话，且一句话说完。
3. **一个屏幕一个主角。** 书库页主角是网格；系列页主角是「继续阅读」；阅读器主角是页面本身。
4. **主次分明的动作层级。** 每屏最多 1 个实心主按钮，2–3 个次级按钮，其余进 `···` 溢出菜单。
5. **反馈只出现一次。** toast 或状态行，二选一，不双播。
6. **暗色不是覆盖，是派生。** 全部颜色走 token，暗色只换 token 值。

## 四、各屏布局重构

### 书库首页（`LibraryView.tsx` + `App.css` `.library-*`）

- 顺序重排为：**标题行（含扫描按钮 + 内联进度）→ 工具栏 → 网格**。「继续阅读」从独立大卡改成标题行右侧的紧凑胶囊按钮，或网格首位的特殊 tile。扫描进度并入按钮内文字（已有 `扫描中 3/20`），删掉外面那行「正在处理 X」。
- 工具栏：搜索框 + 筛选改为**分段控件**（全部 / 收藏 / 最近 / 未匹配），排序保留下拉，计数右对齐不变。
- Tile 去卡片化：删 `.library-tile` 的 border 和背景，封面直接圆角 8px + hover 投影 / 轻微上浮，标题和话数放在封面下方裸排。`min-height: 2.7em` 的双行标题保留。
- 失败列表 `<details>` 移到工具栏右侧一个警告图标 + popover。

### 系列页（`SeriesView.tsx` + `.series-*`）

- Hero 区加封面模糊背景（`filter: blur` + 遮罩即可），封面加投影升到 200px 宽。
- 动作行收敛为：**继续阅读（实心主按钮）+ 收藏 + `···` 菜单**（编辑元数据 / 打开文件夹 / 重新扫描 / 选择封面 / 清除进度全部进菜单）。
- 章节列表从整宽行改为 2–3 列紧凑网格，已读章节降透明度，`current` 章节用左侧色条标记。

### 设置页（`SettingsView.tsx`）

- 四个 panel 加节标题（书架 / 阅读 / 外观与缓存 / 关于），左侧 72px 标签列拉宽对齐。
- **路径改为自动保存**：删「保存路径」按钮，输入失焦或选择文件夹后直接 `persistPaths`，`pathMessage` 改 toast。「高级：索引库路径」折叠保留。
- 「检查更新」结果区只留三态：可更新（版本号 + 安装按钮）/ 已最新 / 未找到。

### 阅读器（`ReaderView.tsx`）

- footer 收敛为：章节名 + 进度条 + 页码，右侧提示句删除。
- 「更多」菜单重构为分组带选中态的设置 popover：阅读模式（翻页 / 滚动 / 双页，单选）、方向（左开 / 右开，单选）、封面单独（开关）、全屏。
- 工具栏 prev/next 箭头按钮可删（点击区域 + 滚轮 + 键盘已覆盖翻页），页码保留。

## 六、风险

1. **测试钉死文案。** `LibraryView.test.tsx`（124 / 125 / 161 行）、`SettingsView.test.tsx`（76 行）断言长提示文案，P0 必须同 PR 更新。`App.test.tsx` 252 / 261、`SeriesView.test.tsx` 75、`ReaderView.test.tsx` 82 行断言的按钮名 / 汇报语**保持原样**作为回归防线。
2. **i18n。** 所有字符串硬编码中文散落在组件里，无提取层。P0 只做删改不做提取；若未来要多语言，P2 前先落一个 `strings.ts` 常量层。
3. **既有习惯。** 侧栏底部状态行是老用户看扫描结果的地方，P0 只去重不删位。分段控件替换筛选 `<select>` 时保留 localStorage 键（`loadLibraryViewPrefs`）兼容旧偏好。
4. **最近更新基线流（不可破坏）。** `baselineCompleted` 的三处分支——按钮文字切换、空状态引导、`establishedBaseline` 汇报——全部原样保留。首次使用路径依旧是「选择书架文件夹 → 导入现有书库 → 基线汇报」。P0 / P1 只动外观层，不动 `useLibrarySession.ts` 的扫描 / 基线逻辑。
5. **P2 主题工程回归面大。** 建议 P2 拆成「token 替换（不改视觉）→ 调 token 值（只改视觉）」两步提交，方便逐屏截图对比。
