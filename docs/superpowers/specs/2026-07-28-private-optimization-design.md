# MangaCon Companion 私人优化设计

日期：2026-07-28  
状态：主人已批准总体方向，等待对本文档化边界的最终复核

## 背景

MangaCon Companion 1.0.17 已能满足当前私人使用需求，主流程已经从截图、鼠标自动化迁移到 SQLite 任务队列。现阶段不需要扩充产品能力或重写技术栈，目标是降低大书架下的重复 I/O、提高数据库写入的原子性，并让异常后的状态更容易判断。

当前只读核验规模为：

- companion DB 中 447 本漫画、33,077 个章节、971,227 张图片；
- 目录指纹文本合计约 35.27 MB，companion DB 文件约 44.6 MiB；
- 447 张封面缓存约 81 MiB；
- MangaCon 数据库备份 212 份，共约 1.35 GiB。

## 设计原则

1. 保持 Windows、固定路径、单用户的私人使用前提，不建设通用商业产品能力。
2. 保持 React + Tauri + Rust + SQLite，不引入服务器、ORM或大型状态框架。
3. 所有行为变更先用失败测试固定，再写最小实现。
4. 不在开发或测试过程中修改真实 MangaCon 数据库、真实 companion DB、封面缓存或既有备份。
5. 每个批次都必须能独立构建、测试和回退；不把无关重构混入功能修改。

## 批次一：构建与数据安全基础

### 1. 恢复统一验证入口

- 将前端运行基线明确为 ES2022，使现有 `Array.prototype.at` 用法能通过 TypeScript 构建。
- 修复当前两个 Clippy 告警，不改变运行行为。
- 增加本地 `verify` 命令，依次运行前端测试、正式构建、Rust 格式检查、Rust 测试和严格 Clippy。
- 不引入远端 CI。

### 2. 版本化 companion DB 迁移

- 使用 `PRAGMA user_version` 顺序执行迁移。
- 对现有无版本数据库执行兼容迁移，不要求删除或重建用户数据。
- 新增 `chapters(comic_id, ordinal, title)` 索引，使章节读取、排序和按漫画删除不再依赖全表扫描。
- 测试覆盖空数据库、现有无版本数据库和重复打开的幂等行为。

### 3. 单本漫画原子同步

- 文件系统扫描在数据库事务之外完成。
- 一本漫画的 `comics` 元数据、标签、章节和目录指纹在一个事务中提交。
- 任意一步失败时整本漫画回滚，不留下章节被删空、部分插入或统计与章节不一致的状态。
- 复用章节插入 prepared statement，避免逐章 autocommit。
- 单本失败应记录为该漫画的扫描错误并继续后续漫画；批次汇总明确报告成功、缺失和失败数量。

### 4. MangaCon 一致性备份与短写事务

- 先进行只读候选发现；没有任何数据库 mutation 时不生成备份。
- 本地章节目录扫描不得发生在 MangaCon 写事务内。
- 确实要写入时，使用 SQLite Online Backup API 将快照写入同目录临时文件。
- 对临时快照执行 `PRAGMA quick_check`，成功后再原子改名为正式备份。
- 只在新的有效备份发布后清理旧备份；仅处理与当前数据库精确匹配的 companion backup 文件名。
- 保留最近 20 份有效备份。开发过程不主动运行真实队列命令，因此不会在本次实现期间删除现有备份。
- 最终写入使用短 `IMMEDIATE` 事务，并在事务内重新确认任务仍需创建、仍未重复。

### 5. 分阶段操作结果

- 数据库提交成功后，MangaCon 重启或弹窗确认失败不得把整个操作描述成“完全失败”。
- 返回结果区分 `databaseCommitted`、备份路径、已创建或重排任务数、重启警告和确认警告。
- 前端明确显示“任务已提交，但后续启动/确认需要人工检查”。
- 数据库提交前的错误仍作为失败返回。

### 6. 全局操作协调与监控器

- App 层维护唯一的互斥 operation，所有会写 companion DB、MangaCon DB、重启 MangaCon 或操纵窗口的按钮共享同一冲突组。
- Rust 后端对 MangaCon mutation 和窗口写操作设置进程内互斥，不能只依赖按钮禁用。
- 每次新任务流程创建新的 operation/run id；过期响应和旧 `finally` 不得覆盖当前状态。
- 自动修复监控每轮开始时重置计数；达到 120 次上限时显示明确超时状态。
- 状态查询发生瞬时错误时进行有限退避重试，不永久终止该轮监控。
- 任务卡片数量直接派生自最新 `activeTasks`，仅在状态尚未加载时使用本次入队数作为临时值。

## 批次二：书架和缓存 I/O

### 1. 版本化目录签名

- 将完整路径清单替换为带 `v2:` 前缀的定长摘要。
- 对漫画保存章节级轻量签名，仅完整扫描发生变化的章节。
- 保留“强制完整扫描”能力，作为目录时间戳异常或人工修复的逃生口。
- 同步开始时批量读取已有签名；未变化的漫画不重复更新数据库时间戳。
- 首次遇到旧版长指纹时按正常扫描生成 v2 数据，不执行一次性全库破坏性迁移。

### 2. 封面缓存

- 缓存目录每轮只创建一次。
- 根据源文件标识、大小和 mtime 判断命中；只有缺失或变化时才读取和复制。
- 新封面先写临时文件，再原子替换目标文件。
- 仅为已导入漫画维护封面，不为无关 MangaCon 记录扩张缓存。

### 3. 阅读器索引

- 打开漫画时优先读取 companion DB 中的章节索引。
- 只在索引缺失、签名变化或用户明确刷新时重新扫描全部章节。
- 打开具体章节时仍从目录读取真实页面，避免数据库缓存隐藏文件缺失。
- 封面和页面图片加载失败时显示路径、重试和重新扫描入口。

## 批次三：维护面收缩

这一批次不自动执行删除，必须根据实际使用习惯再次确认：

- 如果旧截图、红点和鼠标长跑已经不再使用，删除其可写入口、commands、类型和专属测试，仅保留必要的只读窗口诊断。
- 如果仍作为应急备用，则保留功能，但将运行控制器提升到 App 级，增加 run id、页面切换恢复和唯一操作锁。
- 删除确认未使用的 `notify`、opener、`greet`、假保存按钮和遗留数据访问器；`tempfile` 移入 dev-dependencies。
- 旧数据库表只停止新建或访问，不为了少量空间直接破坏性 DROP。

## 数据流

### 书架同步

1. 只读加载漫画和签名缓存。
2. 事务外检查本地目录并构造每本漫画的完整新状态。
3. 每本漫画使用独立短事务提交元数据、标签、章节和签名。
4. 单本失败被隔离并加入汇总，后续漫画继续处理。
5. 前端只接受当前 operation id 对应的结果。

### MangaCon 任务写入

1. 只读读取 MangaCon 候选。
2. 事务外读取 companion 章节与本地目录，形成待处理集合。
3. 集合为空时直接返回，不生成备份。
4. 创建并验证 SQLite 快照。
5. 开启短 `IMMEDIATE` 事务，重新校验、去重并提交。
6. 返回数据库提交结果，再执行重启和弹窗确认。
7. 后续步骤失败以 warning 返回，不抹去已提交事实。

## 错误处理

- 文件系统错误关联到具体漫画或缓存文件，不以模糊的全局错误覆盖已完成结果。
- companion DB 单本事务失败必须回滚。
- MangaCon DB 在备份验证失败时零写入。
- 备份清理失败不回滚已完成数据库操作，但必须作为 warning 返回并保留新备份。
- 后端互斥冲突返回可识别错误，前端显示当前正在执行的操作。
- 不自动吞掉重启、确认、监控超时和图片加载失败。

## 测试与验收

批次一至少覆盖：

- `npm run build` 成功，完整 `verify` 命令退出码为 0；
- schema 迁移创建索引、可重复执行并保留旧数据；
- 单本章节替换中途失败时旧状态完整保留；
- no-op queue、repair、resume 不创建备份；
- 在线备份通过 `quick_check`，目录中最多保留 20 份匹配备份；
- 文件扫描发生在 MangaCon 写事务之外；
- 数据已提交但重启失败时返回 committed + warning；
- 并发操作只能有一个进入后端；
- 监控达到上限后，新一轮会重新获得完整检查次数；
- 瞬时状态错误按上限重试，最终超时有可见提示。

批次二至少覆盖：

- v2 签名固定长度且文件变化会改变摘要；
- 未变化章节不会重新枚举所有图片或写数据库；
- 封面命中不重写文件，变化时原子替换；
- 阅读器优先使用缓存，强制刷新能重建索引；
- 图片失败进入可见错误状态。

所有批次最终运行：

```text
npm test -- --run
npm run build
cargo fmt --manifest-path src-tauri/Cargo.toml --all -- --check
cargo test --manifest-path src-tauri/Cargo.toml
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets --all-features -- -D warnings
```

## 明确不做

- 不修改固定的 MangaCon、书架、收藏导出和 companion DB 默认路径。
- 不引入账号、多用户、网络服务、远程日志、遥测或商业发布流程。
- 不增加 ORM、通用插件系统、列表虚拟化或并行扫盘。
- 不擅自修改 MangaCon 的 journal mode 或创建未知外部 schema。
- 不在未确认使用情况前删除旧截图/鼠标自动化。
